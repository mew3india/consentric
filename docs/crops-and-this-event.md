# CROPS and This Event

Ethereum isn't just a technology — it's a set of values. The community often summarizes them as **CROPS**: Censorship Resistance, Open Source, Privacy, and Security. This event uses those values as the actual design brief, not just a tagline.

Here's what each one means in the context of Consentric.

---

## Censorship Resistance

A health record stored in a hospital's database exists at the mercy of that hospital. They can lose it, alter it, restrict access to it, or hand it over to a third party without the patient's knowledge. A contract deployed to Ethereum can't be taken down by any single party — not the hospital, not the government, not the developer who wrote it.

**At this event:** The contracts you build will be deployed to a network that no one controls. A patient's consent decisions, once recorded, can't be silently overridden. That's not a feature — it's an architectural guarantee.

## Open Source

If a system controls your medical records, you should be able to read its source code. You should be able to verify that it does what it claims. You should be able to fork it and improve it.

**At this event:** Every line of code ships to a public GitHub repository under the MIT license. Your submission isn't locked behind a company's proprietary stack — it's available to anyone who wants to learn from it, audit it, or build on it. The event itself is open source.

## Privacy

"Transparent" and "private" sound like opposites, but they're not — not on Ethereum. The blockchain is transparent in the sense that anyone can verify that a transaction happened. But the *content* of that transaction can be kept private through techniques like selective disclosure and zero-knowledge proofs.

**At this event:** The selective-disclosure track is entirely about this tension. Can you prove that a patient is vaccinated without revealing their full medical history? Can you prove someone is over 18 without revealing their date of birth? That's the challenge — transparency where it matters, privacy everywhere else.

## Security

Health data is some of the most sensitive information that exists. A breach doesn't just leak a password — it leaks diagnoses, treatments, conditions. The security model for health records needs to be better than "we promise to keep the database safe."

**At this event:** You're building with cryptographic access control, immutable audit trails, and on-chain consent records. Security isn't a checkbox you tick at the end — it's the foundation everything else is built on. The access-audit-trail track exists specifically so that every data access is logged permanently and transparently.

---

## The Bigger Picture

India's Ayushman Bharat Digital Mission is moving health records onto digital systems. That's happening whether or not the privacy and consent infrastructure is ready. The question isn't *if* health data goes on-chain — it's *how*, and *who controls the design*.

This event is a small, concrete step toward answering that question with Ethereum's values in mind. You're not just building a hackathon project — you're prototyping what patient-controlled health records could actually look like.
